[FLUJO 1] CREAR RECUERDO / CITA INSTANTÁNEA
================================================================================

PARTNER - "Cita Instantánea" 📱
────────────────────────────────
1. Partner abre app → Tab Lugares o FAB "+" → Modal "Nueva Cita"

2. PASO 1: Captura de fotos
   - Abre selector de fotos (cámara o galería)
   - Puede seleccionar múltiples fotos
   - EN PARALELO (invisible):
     a. Lee EXIF de SOLO la primera foto → extrae GPS si existe
     b. Si no tiene GPS en EXIF → llama navigator.geolocation
     c. Si ambos fallan → campo ubicación quedará vacío
   - Fotos se guardan temporalmente en memoria (no suben aún)

3. PASO 2: Formulario simplificado (con datos pre-detectados)
   - Ubicación: Si detectó GPS → muestra "📍 [Nombre del lugar]" (editable)
   - Título: Opcional (placeholder: "Sin título")
   - Fecha: Default HOY, puede cambiarse
   - Tags: Selector rápido (🎬 cine | 🍽️ comida | ❤️ romántico | 🏍️ aventura | 🎉 especial)
   - adminNotes: OCULTO (no aplica para partner)

4. GUARDAR → Subida optimista con estados claros
   - ONLINE:
     a. Sube fotos a Storage en paralelo (con progress bar)
     b. Llama createMemory() con URLs de Storage
     c. Llama findOrCreatePlace() → actualiza pin en mapa
     d. Backend analiza tags para auto-completar bingo (si aplica)
     e. UI muestra memoria inmediatamente (loading → ✅ Guardado)
   
   - OFFLINE:
     a. Guarda en IndexedDB con status: "pending"
     b. UI muestra con badge "📤 Pendiente de subir"
     c. Service Worker registra sync event
     d. Cuando vuelva conexión:
        - Procesa queue en orden FIFO (más viejo primero)
        - Sube 1 foto cada 3 segundos (rate limiting)
        - Máx 3 reintentos por foto con backoff exponencial
        - Notificación: "✅ 5 fotos subidas correctamente"

ADMIN - "Crear Recuerdo" 💻
────────────────────────────
1. Admin Dashboard → Recuerdos → + Nuevo Recuerdo

2. USA EL MISMO MemoryForm.jsx que partner
   - Diferencias:
     a. Campo "adminNotes" VISIBLE (notas privadas)
     b. Puede elegir "uploadedBy: user1 o user2"
     c. Selector de ubicación más completo (con mapa)

3. GUARDAR → mismo flujo que partner (createMemory + findOrCreatePlace)

[FLUJO 5] BINGO DE CITAS
================================================================================

CASO A: COMPLETAR PROACTIVAMENTE (desde bingo)
──────────────────────────────────────────────
1. Partner → Tab Bingo → Tap casilla vacía: "Ir al cine 🎬"

2. Verifica: ¿Está habilitada por admin?
   - NO → Toast: "Esta casilla estará disponible pronto 🔒"
   - SÍ → Continúa

3. Abre modal de Cita Instantánea con DATOS PRE-RELLENADOS:
   - title: "Ir al cine" (editable)
   - tags: ["cine"] (pre-seleccionado, puede agregar más)
   - placeCategory: "entertainment" (sugerido)
   - bingoContext: { categoryId: "cita_cine", source: "proactive" }

4. Al GUARDAR:
   - createMemory() guarda el recuerdo normal
   - completeBingoSquare(categoryId, memoryId) marca casilla
   - Animación: ✨ Casilla se llena con foto principal
   - Confetti + sonido si es la PRIMERA del mes

CASO B: SUBIR CITA NORMAL (autodetección retroactiva)
─────────────────────────────────────────────────────
1. Partner sube cita desde galería con tag "cine"

2. Backend (en createMemory Cloud Function):
   - Analiza tags: ["cine", "romántico"]
   - Busca en bingoBoard casillas NO completadas con esos tags
   - Encuentra: "cita_cine" (vacía) y "cita_romantica" (vacía)
   - Guarda en memory.bingoSuggestions: ["cita_cine", "cita_romantica"]

3. Frontend detecta bingoSuggestions en la respuesta:
   - Muestra BottomSheet modal:
     ┌─────────────────────────────────────┐
     │ 🎉 ¡Completaste casillas del bingo! │
     │ Esta cita puede completar:          │
     │ • Ir al cine 🎬                     │
     │ • Cita romántica ❤️                 │
     │ ¿Cuál quieres marcar?               │
     │ [Elegir una] [Elegir ambas]         │
     │ [No, gracias]                       │
     └─────────────────────────────────────┘

4. Partner elige UNA o AMBAS → Backend actualiza bingoBoard

CASO C: MÚLTIPLES CITAS EN UN DÍA
─────────────────────────────────
Ejemplo: Sábado → cine (tarde) + cena (noche)

1. CITA 1 (4:00 PM): Van al cine
   - Suben fotos con tags: ["cine"]
   - Sugiere completar: "Ir al cine 🎬"
   - Partner acepta → casilla marcada

2. CITA 2 (8:00 PM): Cena romántica
   - Suben fotos con tags: ["comida", "romántico"]
   - Sugiere completar: "Cena romántica ❤️"
   - Partner acepta → otra casilla marcada

Resultado: 2 casillas completadas en 1 día ✅
(Son dos memories SEPARADAS, cada una con su ubicación, fotos, hora)

CASO D: DESCOMPLETAR CASILLA (solo admin)
─────────────────────────────────────────
1. Admin → Panel Bingo → Tap casilla completada → ⚙️ Opciones

2. Modal: "¿Descompletar esta casilla?"

   - Razón (opcional): "Se equivocaron de casilla"

3. Confirmar → Backend:

   - bingoBoard.categories[X].completedMemoryId = null
   - bingoBoard.categories[X].completedAt = null

[FLUJO 6] INSTANTÁNEAS (SNAPSHOTS)
================================================================================

ENVIAR SNAPSHOT
───────────────
1. Admin o Partner → FAB 📷 o SnapshotButton

2. Se abre SnapshotCreator:
   - iOS: Selector nativo (cámara + galería)
   - Android: Cámara trasera directa (con flip)

3. Toma/elige foto → Vista previa con filtro Polaroid
   - Puede agregar mensaje corto (max 50 caracteres)

4. "Enviar 💌" → Sube a Storage + createSnapshot()
   - Online:
     a. Sube a /snapshots/{uuid}/photo.jpg
     b. Crea doc en Firestore /snapshots/{uuid}
     c. Toast: "¡Enviado! ✓"
   
   - Offline:
     a. Guarda en IndexedDB (igual que memories)
     b. Badge: "1 snapshot pendiente 📤"

VER SNAPSHOT RECIBIDO
─────────────────────
1. Receptor → SnapshotButton con anillo de progreso

2. Anillo muestra:
   - Completo (360°) = no hay snapshots sin ver
   - Parcial = hay N snapshots sin ver
   - Badge rojo: "3" (si hay 3 sin ver)

3. Tap → Query Firestore:
   - WHERE createdBy != currentUserId
   - WHERE viewedBy NOT IN currentUserId
   - WHERE expiresAt > now()
   - ORDER BY createdAt ASC (más vieja primero)

4. Abre SnapshotOverlay con la PRIMERA de la queue:
   - Muestra foto en formato Pillow/Polaroid
   - Timer de visualización (configurable en snapshotConfig)
   - Contador: "1 de 3" si hay más
   
5. Al terminar timer o swipe derecha:
   - Marca viewedByPartner = true, viewedAt = now
   - Si hay más en queue → muestra siguiente
   - Si no → cierra overlay con animación

6. Incitación: "¿Enviarle una también? 📸"

EXPIRACIÓN (24 horas)
─────────────────────
1. Cloud Function scheduled — cada 6 horas

2. Query: snapshots con expiresAt < now() && !isArchived

3. Para cada snapshot expirado:
   - Si viewedBy.includes(recipientId):
     - Marca isArchived = true
     - Aparece en galería normal automáticamente
   
   - Si NO fue visto:
     - También marca isArchived = true
     - Aparece en galería con badge "📥 No visto"

4. Opcional: Después de 7 días archivado → eliminar de Storage

VISUALIZACIÓN EN GALERÍA (después de 24hrs)
───────────────────────────────────────────
1. Partner/Admin → Tab Galería

2. Snapshots archivados aparecen:
   - Mezclados cronológicamente con memories
   - Badge: "📸 Snapshot" (para distinguir)
   - Si no fue visto a tiempo: badge "📥 No visto"
   - Puede verlos normalmente como cualquier foto

[FLUJO 8] SISTEMA OFFLINE-FIRST
================================================================================

OBJETIVO
────────
Que ella pueda subir citas Y snapshots sin conexión, y que se sincronicen automáticamente cuando vuelva internet.

ARQUITECTURA DE QUEUE
─────────────────────
1. UI Layer (React Components)
   ↓
2. useOfflineQueue Hook (gestiona estado local)
   ↓
3. IndexedDB (almacenamiento persistente)
   ↓
4. Service Worker (sincronización en background)
   ↓
5. Firebase Storage + Firestore (destino final)

ESTRATEGIA DE SINCRONIZACIÓN
────────────────────────────
1. Background Sync: Registra evento `sync` cuando el dispositivo detecta que volvió a estar online

2. Rate Limiting: Procesa la queue secuencialmente (ej. 1 foto cada 3 seg) para no ahogar la conexión si volvió con 3G inestable

3. Retry Mechanism: Máximo 3 intentos con backoff exponencial. Si falla 3 veces, marca el status local de la cola como `failed`

4. Cleanup: Cuando se completa el subido, elimina el blob local para ahorrar memoria en el dispositivo móvil

UI INDICATORS PARA OFFLINE
──────────────────────────
1. Galería/Mapa: Fotos recién tomadas (en estado offline) se muestran con filtro o un overlay de loader translúcido `[💭 Subiendo...]`

2. Navbar/Dashboard: Badge dinámico `[📤 3 pendientes]` si hay elementos encolados

3. Notificación: Toast in-app `[✅ 5 fotos subidas]` cuando el Service Worker procesa la cola con éxito en background

LÍMITE DE STORAGE EN INDEXEDDB
──────────────────────────────
- Máximo: 100 MB o 50 items pendientes (lo que se alcance primero)
- Por foto: Max 10 MB (comprimir antes de guardar)
